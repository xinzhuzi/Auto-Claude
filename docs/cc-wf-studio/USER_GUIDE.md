## 简介

**Workflow Studio** 是 Auto-Claude 的可视化工作流编辑器，让你通过拖拽节点的方式构建复杂的自动化工作流。

### 核心功能

- 🎨 **可视化编辑** - 拖拽式节点编辑器
- 🔄 **12 种节点类型** - 支持各种操作
- ⚡ **实时执行** - 即时执行工作流
- 📊 **进度跟踪** - 实时查看执行进度
- 💾 **工作流管理** - 保存、加载、复制工作流

### 适用场景

- 自动化重复任务
- 批量文件处理
- 多步骤代码审查
- 集成多个工具和服务
- 自定义自动化流程

## 快速开始

### 1. 打开 Workflow Studio

在 Auto-Claude 中：

1. 点击左侧边栏的 **"工作流"** 图标（🔄）
2. 或使用快捷键 **`F`** 切换到工作流视图

### 2. 创建第一个工作流

1. 点击 **"创建工作流"** 按钮
2. 输入工作流名称（例如："Hello World"）
3. 点击 **确定**

### 3. 添加节点

1. 从左侧 **节点调色板** 拖拽节点到画布
2. 连接节点：从一个节点的输出点拖拽到另一个节点的输入点
3. 配置节点：点击节点，在右侧属性面板中配置参数

### 4. 执行工作流

1. 点击顶部 **"执行"** 按钮
2. 查看右侧 **执行面板** 的实时进度
3. 执行完成后查看结果

## 创建工作流

### 工作流结构

每个工作流必须包含：
- ✅ **1 个 Start 节点** - 工作流入口
- ✅ **1 个 End 节点** - 工作流出口
- ✅ **1+ 个任务节点** - 实际操作

### 示例：简单的问候工作流

```
Start → Prompt (说 "Hello") → End
```

**步骤**：

1. 从调色板拖拽 **Start** 节点到画布
2. 拖拽 **Prompt** 节点到画布
3. 拖拽 **End** 节点到画布
4. 连接节点：Start → Prompt → End
5. 配置 Prompt 节点：
   - 提示词：`请用中文说 "Hello, World!"`
6. 保存工作流
7. 执行工作流

---

## 节点类型

### 1. Start 节点

**用途**: 工作流入口点

**配置**: 无需配置

**注意事项**:
- 每个工作流必须有且仅有 1 个 Start 节点
- Start 节点没有输入连接
- Start 节点必须有输出连接

---

### 2. End 节点

**用途**: 工作流出口点

**配置**: 无需配置

**注意事项**:
- 每个工作流必须有且仅有 1 个 End 节点
- End 节点没有输出连接
- End 节点必须有输入连接

---

### 3. Prompt 节点

**用途**: 发送提示词到 Claude

**配置**:
- **提示词** (Prompt): 要发送的消息
- **模型** (Model): Claude 模型选择（可选）
  - `claude-sonnet-4-5-20250929` (默认)
  - `claude-opus-4-5-20250929`

**示例**:
```
提示词: 请总结以下内容：
{{input_text}}

模型: claude-sonnet-4-5-20250929
```

---

### 4. Skill 节点

**用途**: 执行预定义技能

**配置**:
- **技能名称** (Skill Name): 技能标识符
- **提示词** (Prompt): 技能提示词（可选）

**可用技能**:
- `code-reviewer` - 代码审查
- `test-generator` - 测试生成
- `doc-generator` - 文档生成
- ...（更多技能由 Auto-Claude 提供）

**示例**:
```
技能名称: code-reviewer

提示词: 请审查以下代码文件：
src/main.py
```

---

### 5. MCP 节点

**用途**: 调用 MCP 工具

**配置**:
- **服务器** (Server): MCP 服务器名称
- **工具** (Tool): 工具名称
- **参数** (Parameters): 工具参数（JSON 格式）

**示例**:
```
服务器: filesystem
工具: read_file
参数: {
  "file_path": "/path/to/file.txt"
}
```

---

### 6. If/Else 节点

**用途**: 条件分支

**配置**:
- **条件** (Condition): 布尔表达式
- **True 分支** (True Branch): 条件为真时执行的分支
- **False 分支** (False Branch): 条件为假时执行的分支

**示例**:
```
条件: {{error_count}} > 0

True 分支: handle_error
False 分支: continue
```

**注意事项**:
- 条件表达式支持简单比较运算
- 复杂逻辑建议使用 Switch 节点

---

### 7. Switch 节点

**用途**: 多路分支

**配置**:
- **表达式** (Expression): 要匹配的值
- **Case 列表** (Cases): 多个分支定义

**示例**:
```
表达式: {{file_type}}

Cases:
- 值: "python" → 分支: process_python
- 值: "javascript" → 分支: process_js
- 值: "markdown" → 分支: process_md
- 默认 → 分支: process_other
```

---

### 8. Ask User 节点

**用途**: 请求用户输入

**配置**:
- **问题** (Question): 要问用户的问题
- **选项** (Options): 可选答案列表
- **多选** (Multi Select): 是否允许多选

**示例**:
```
问题: 请选择要使用的编程语言：

选项:
- Python
- JavaScript
- TypeScript

多选: false
```

**注意事项**:
- 执行时会暂停工作流
- 用户必须选择后才会继续
- 适用于需要人工确认的场景

---

### 9. SubAgent 节点

**用途**: 启动子代理

**配置**:
- **代理名称** (Agent Name): 子代理标识符
- **提示词** (Prompt): 任务描述
- **描述** (Description): 代理角色描述

**示例**:
```
代理名称: code-reviewer

提示词: 请审查 src/utils.py 代码质量

描述: 专注于代码风格、性能和安全性
```

---

### 10. Branch 节点

**用途**: 扇出多个并行分支

**配置**:
- **分支列表** (Branches): 分支名称列表

**示例**:
```
分支列表:
- branch_a
- branch_b
- branch_c
```

**使用场景**:
- 并行执行多个任务
- 同时处理多个文件
- 批量操作

## 执行工作流

### 执行方式

#### 1. 手动执行

1. 打开工作流
2. 点击顶部 **"执行"** 按钮
3. 查看执行面板的进度

#### 2. 快捷键执行

- `Ctrl + Enter` (Windows/Linux)
- `Cmd + Enter` (macOS)

### 执行控制

#### 暂停执行

- 点击 **"暂停"** 按钮
- 工作流会在当前节点完成后暂停

#### 恢复执行

- 点击 **"继续"** 按钮
- 工作流从暂停处继续

#### 取消执行

- 点击 **"停止"** 按钮
- 工作流立即终止

### 执行状态

| 状态 | 说明 |
|------|------|
| 🟡 Pending | 等待执行 |
| 🔵 Running | 正在执行 |
| ⏸️ Paused | 已暂停 |
| ✅ Completed | 执行完成 |
| ❌ Failed | 执行失败 |
| 🚫 Cancelled | 已取消 |

### 查看执行结果

#### 实时进度

执行面板显示：
- 进度条（0-100%）
- 当前执行节点
- 已完成节点数

#### 执行日志

点击执行面板的 **"查看日志"** 按钮，查看：
- 每个节点的执行时间
- 节点输出结果
- 错误信息（如果有）

## 最佳实践

### 1. 工作流设计

#### 保持简洁

❌ **不好的做法**:
```
Start → [100 个节点] → End
```

✅ **好的做法**:
```
Start → [子工作流 1] → [子工作流 2] → End
```

#### 模块化

将复杂工作流拆分成多个子工作流：
- 每个子工作流负责一个独立任务
- 使用 SubAgent 节点调用子工作流
- 提高可维护性和复用性

### 2. 节点使用

#### Prompt 节点

✅ **清晰具体**:
```
请将以下文本翻译成中文：
{{text}}
```

❌ **模糊不清**:
```
处理这个文本
```

#### Skill 节点

✅ **选择合适技能**:
- 代码审查 → `code-reviewer`
- 测试生成 → `test-generator`
- 文档生成 → `doc-generator`

#### If/Else 节点

✅ **简单条件**:
```
{{error_count}} > 0
```

❌ **复杂逻辑**（使用 Switch）:
```
{{status}} == "success" && {{count}} > 10 && {{type}} == "file"
```

### 3. 错误处理

#### 使用 Try-Catch 模式

```
Start → Task → IfElse (检查错误)
                ├─ True → 错误处理 → End
                └─ False → 继续任务 → End
```

#### 记录错误

在错误分支添加 Prompt 节点：
```
提示词: 记录错误到日志文件：
错误: {{last_error}}
时间: {{current_time}}
```

### 4. 性能优化

#### 并行执行

使用 Branch 节点并行处理：
```
Start → Branch → [任务 1] ──┐
               → [任务 2] ──┤→ End
               → [任务 3] ──┘
```

#### 避免重复调用

❌ **不好**:
```
Task 1 → 读取文件 → 处理 → 写入
Task 2 → 读取文件 → 处理 → 写入
```

✅ **好**:
```
读取文件 → Branch → [处理 1] ──┐
                   → [处理 2] ──┤→ 写入
```

## 故障排除

### 常见问题

#### 1. 工作流无法执行

**症状**: 点击"执行"后没有反应

**可能原因**:
- ❌ 缺少 Start 或 End 节点
- ❌ 节点未正确连接
- ❌ 工作流未保存

**解决方案**:
1. 检查是否有 Start 和 End 节点
2. 验证所有节点都已连接（没有悬空的节点）
3. 保存工作流后重试

---

#### 2. 执行卡住不动

**症状**: 执行进度停在某个节点

**可能原因**:
- ⚠️ 节点正在等待用户输入（Ask User 节点）
- ⚠️ 网络请求超时
- ⚠️ 资源锁定

**解决方案**:
1. 检查是否有 Ask User 节点等待输入
2. 检查网络连接
3. 尝试暂停后继续
4. 如果仍然卡住，取消执行

---

#### 3. 节点执行失败

**症状**: 执行面板显示错误

**可能原因**:
- ❌ 节点配置错误
- ❌ MCP 服务器未连接
- ❌ 权限不足

**解决方案**:
1. 查看执行日志中的错误消息
2. 检查节点配置是否正确
3. 验证 MCP 服务器状态
4. 检查文件/目录权限

---

#### 4. 进度不更新

**症状**: 进度条长时间不动

**可能原因**:
- ⚠️ 节点执行时间较长（正常）
- ⚠️ 通信延迟

**解决方案**:
1. 等待更长时间（某些操作可能需要几分钟）
2. 查看执行日志确认节点是否在运行
3. 如果超过 5 分钟无响应，考虑取消执行

### 调试技巧

#### 1. 使用日志节点

在关键位置添加 Prompt 节点记录中间状态：
```
提示词: 调试信息：
当前变量: {{my_var}}
节点结果: {{last_result}}
```

#### 2. 分段测试

将长工作流拆分成多个短工作流，分别测试：
```
[工作流 A: 数据准备] → 测试
[工作流 B: 数据处理] → 测试
[工作流 C: 结果输出] → 测试
```

#### 3. 查看执行日志

每次执行后查看完整日志：
1. 点击执行面板的 **"查看日志"**
2. 查找错误消息（红色）
3. 检查每个节点的输出

## 高级功能

### 1. 变量引用

在节点配置中使用 `{{变量名}}` 引用之前节点的输出：

```
节点 1 (Prompt):
  提示词: 读取文件内容
  输出变量: file_content

节点 2 (Prompt):
  提示词: 分析以下内容：
  {{file_content}}
```

### 2. 模板系统

使用工作流模板快速开始：
1. 点击 **"从模板创建"**
2. 选择合适的模板
3. 根据需要修改

### 3. 工作流版本控制

每次保存工作流都会创建版本：
- 查看版本历史
- 回滚到旧版本
- 比较版本差异
