# 任务优化功能

## 概述

任务优化功能通过 AI 分析用户输入的任务描述，自动优化提示词并给出是否使用 Worktree 隔离模式的建议。

## 数据流

### 请求数据

```typescript
interface OptimizeTaskRequest {
  task_description: string;  // 原始任务描述
  project_path: string;      // 项目路径
  target_paths?: string[];   // 用户 @ 引用的文件/文件夹

```

### 响应数据

```typescript
interface OptimizeTaskResponse {
  optimized_description: string;              // 优化后的描述
  worktree_recommendation: {
    use_worktree: boolean;                    // 是否推荐 worktree
    reason: string;                           // 推荐原因

  };
  improvements: string[];                     // AI 做了哪些优化
}
```

## AI 优化逻辑

### 系统提示词

AI 被指示执行两个任务：
1. **优化任务描述** - 使描述更清晰、具体、易于执行
2. **Worktree 推荐** - 分析任务特征判断是否需要隔离模式

### Worktree 推荐规则

| 条件 | 推荐 |
|------|------|
| 设计/文档类任务，目标文件夹 >50 个文件 | ✅ 使用 |
| 大面积重构、迁移、架构修改 | ✅ 使用 |
| 任务复杂度高（多模块、多文件） | ✅ 使用 |
| 用户明确提到 worktree/隔离/独立分支 | ✅ 使用 |
| 简单单文件修改、bug 修复 | ❌ 不使用 |

### 文档类任务额外检查

如果检测到文档类任务（包含 "文档"、"document"、"设计"、"design" 等关键词），会额外扫描目标文件夹：

```python
def should_use_worktree_for_doc_task(project_dir, target_paths):
    # 如果目标文件夹包含 >50 个文本文件，推荐 worktree
    text_extensions = {'.md', '.txt', '.rst', '.json', '.yaml', ...}
    text_file_count = sum(1 for f in full_path.rglob('*') 
                          if f.suffix.lower() in text_extensions)
    return text_file_count > 50
```

## 认证方式

任务优化功能支持两种认证方式，**API Profile 优先**：

### 认证优先级

```
1. API Profile (用户配置的 API Key) - 优先使用
2. OAuth (Claude Code OAuth Token) - 备选
```

### API Profile 模式

当用户在设置中配置了 API Profile 并激活时，使用该 Profile 的凭证：

```typescript
// 获取激活的 API Profile 环境变量
const apiProfileEnv = await getAPIProfileEnv();
const isApiProfileActive = Object.keys(apiProfileEnv).length > 0;

if (isApiProfileActive) {
  // 使用 API Profile 的环境变量
  // ANTHROPIC_AUTH_TOKEN, ANTHROPIC_BASE_URL, ANTHROPIC_MODEL 等
}
```

### OAuth 模式

当没有激活的 API Profile 时，回退到 OAuth 认证：

```typescript
if (!isApiProfileActive) {
  // 获取 OAuth Profile 环境变量
  const profileResult = getBestAvailableProfileEnv();
  profileEnv = profileResult.env;
  
  // 支持自动切换到备用 Profile（当主 Profile 被限流时）
  if (profileResult.wasSwapped) {
    debug('Using alternative profile:', profileResult.profileName);
  }
}
```

### getAPIProfileEnv 函数

`apps/frontend/src/main/services/profile/profile-service.ts`:

```typescript
export async function getAPIProfileEnv(): Promise<Record<string, string>> {
  const file = await loadProfilesFile();
  
  // 如果没有激活的 Profile，返回空对象（OAuth 模式）
  if (!file.activeProfileId) {
    return {};
  }
  
  const profile = file.profiles.find(p => p.id === file.activeProfileId);
  if (!profile) {
    return {};
  }
  
  // 映射 Profile 字段到 SDK 环境变量
  return {
    ANTHROPIC_BASE_URL: profile.baseUrl,
    ANTHROPIC_AUTH_TOKEN: profile.apiKey,
    ANTHROPIC_MODEL: profile.models?.default,
    ANTHROPIC_DEFAULT_HAIKU_MODEL: profile.models?.haiku,
    ANTHROPIC_DEFAULT_SONNET_MODEL: profile.models?.sonnet,
    ANTHROPIC_DEFAULT_OPUS_MODEL: profile.models?.opus,
  };
}
```

### 环境变量合并顺序

Python 子进程的环境变量按以下顺序合并（后者覆盖前者）：

```typescript
env: {
  ...process.env,           // 系统环境变量
  ...pythonEnv,             // Python 环境 (PYTHONPATH)
  ...autoBuildEnv,          // 后端 .env 文件
  ...profileEnv,            // OAuth Profile (仅 OAuth 模式)
  ...apiProfileEnv,         // API Profile (优先)
  ...oauthModeClearVars,    // OAuth 模式清理变量
}
```

### OAuth 模式清理

当使用 OAuth 模式时，需要清理可能残留的 API Profile 环境变量：

```typescript
const oauthModeClearVars = getOAuthModeClearVars(apiProfileEnv);
// 如果 apiProfileEnv 为空（OAuth 模式），返回清理变量
// 防止旧的 ANTHROPIC_* 变量干扰
```

## 超时处理

- 默认超时：120 秒
- 超时后自动终止 Python 子进程
- 返回友好错误信息

## 错误处理

| 错误类型 | 处理方式 |
|----------|----------|
| 后端未找到 | 返回 "Backend not found" 错误 |
| 认证失败 | 返回认证提示信息 |
| AI 响应解析失败 | 返回原始描述，worktree 推荐为 false |
| 超时 | 终止进程，返回超时错误 |
