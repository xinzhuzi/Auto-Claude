# 合并执行步骤

> 详细的可执行步骤，包含每个文件的处理方式

---

## 1. 准备工作

### 1.1 检查当前状态

```bash
cd /Users/zhengbingjin/Project/Github/Auto-Claude

# 检查工作目录是否干净
git status

# 如果有未提交的修改，先处理
git stash save "合并前暂存 $(date +%Y%m%d)"
```

### 1.2 创建备份分支

```bash
# 创建备份
git branch backup/pre-merge-20260221

# 确认备份
git branch | grep backup
```

### 1.3 确保在正确分支

```bash
git checkout develop
git pull origin develop
```

---

## 2. 添加上游源

### 2.1 使用本地 temp 目录作为上游

```bash
# 如果已存在，先删除
git remote remove local-upstream 2>/dev/null || true

# 添加本地目录为 remote (比网络 fetch 更快更可靠)
git remote add local-upstream /Users/zhengbingjin/Project/temp/Auto-Claude

# 验证
git remote -v
# 应该看到:
# local-upstream  /Users/zhengbingjin/Project/temp/Auto-Claude (fetch)
# local-upstream  /Users/zhengbingjin/Project/temp/Auto-Claude (push)
```

### 2.2 获取上游更新

```bash
git fetch local-upstream
```

---

## 3. 预览差异

### 3.1 查看上游新提交

```bash
# 查看待合并的提交
git log develop..local-upstream/develop --oneline

# 统计数量
git log develop..local-upstream/develop --oneline | wc -l
```

### 3.2 查看文件变化

```bash
# 统计文件变化
git diff develop local-upstream/develop --stat

# 查看具体文件列表
git diff develop local-upstream/develop --name-only > /tmp/changed_files.txt
```

### 3.3 查看冲突风险

```bash
# 查看双方都修改的文件
git diff develop local-upstream/develop --name-only | while read f; do
  if git show develop:"$f" >/dev/null 2>&1; then
    echo "冲突风险: $f"
  fi
done
```

---

## 4. 执行合并

### 4.1 开始合并

```bash
git merge local-upstream/develop --no-commit
```

### 4.2 查看冲突状态

```bash
# 查看冲突文件
git status | grep "both modified"

# 统计冲突数量
git status | grep -c "both modified"
```

## 5. 冲突解决指南

### 5.1 高优先级冲突文件

#### `apps/frontend/src/main/ipc-handlers/index.ts`

**冲突原因**: 双方都新增了 handler 导出

**解决方式**:
```bash
# 1. 查看双方版本
git show :2:apps/frontend/src/main/ipc-handlers/index.ts > /tmp/ours.ts
git show :3:apps/frontend/src/main/ipc-handlers/index.ts > /tmp/theirs.ts

# 2. 手动合并: 保留上游的导出结构 + 添加本地独有的 handlers
# 本地独有 handlers:
# - code-server-handlers
# - logger-handlers
# - mcp-workflow-handlers
# - novel-handlers
# - skill-handlers

# 3. 标记解决
git add apps/frontend/src/main/ipc-handlers/index.ts
```

#### `apps/frontend/src/main/terminal/terminal-manager.ts`

**冲突原因**: 上游添加了 XState 终端状态机

**解决方式**:
```bash
# 1. 优先采用上游版本 (包含 XState 重构)
git checkout --theirs apps/frontend/src/main/terminal/terminal-manager.ts

# 2. 如果本地有定制逻辑，需要手动添加回来
# 本地可能有的定制:
# - 代理终端相关
# - 终端颜色修改

git add apps/frontend/src/main/terminal/terminal-manager.ts
```

#### `apps/frontend/src/renderer/stores/task-store.ts`

**冲突原因**: 上游移除了 TaskStateMachine，改用 XState

**解决方式**:
```bash
# 优先采用上游版本
git checkout --theirs apps/frontend/src/renderer/stores/task-store.ts
git add apps/frontend/src/renderer/stores/task-store.ts
```

#### `apps/frontend/src/renderer/stores/terminal-store.ts`

**冲突原因**: 上游添加了 XState terminal machine

**解决方式**:
```bash
# 优先采用上游版本
git checkout --theirs apps/frontend/src/renderer/stores/terminal-store.ts
git add apps/frontend/src/renderer/stores/terminal-store.ts
```

#### `apps/frontend/package.json`

**冲突原因**: 依赖和配置差异

**解决方式**: 手动合并
```bash
# 1. 查看双方版本
git show :2:apps/frontend/package.json > /tmp/ours.json
git show :3:apps/frontend/package.json > /tmp/theirs.json

# 2. 合并规则:
# - name: 保留本地 "AI员工"
# - version: 使用上游 "2.7.6"
# - dependencies: 合并双方
#   - 上游新依赖: 全部引入
#   - 本地独有依赖: driver.js, reactflow, react-resizable-panels 保留
# - build 配置: 保留本地 nsis x64 配置

# 3. 编辑后标记
git add apps/frontend/package.json
```

## 8. 回滚方案

### 8.1 合并前回滚

```bash
git merge --abort
```

### 8.2 合并后回滚 (未推送)

```bash
git reset --hard backup/pre-merge-20260221
```

### 8.3 已推送后回滚

```bash
git revert -m 1 HEAD
git push origin develop
```
