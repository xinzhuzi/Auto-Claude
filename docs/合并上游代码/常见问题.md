# 合并常见问题

---

## Q1: 如何查看具体某个文件的差异？

```bash
# 查看某个文件的详细差异
git diff develop local-upstream/develop -- apps/frontend/src/main/agent/agent-manager.ts

# 只看文件变化统计
git diff develop local-upstream/develop --stat -- apps/frontend/src/main/
```

## Q2: 合并过程中想暂停怎么办？

```bash
# 如果还没 commit，可以中止合并
git merge --abort

# 如果已经部分解决，可以先保存
git stash
```

## Q3: 如何恢复单个文件到合并前的状态？

```bash
# 恢复到备份分支的版本
git checkout backup/pre-merge-20260221 -- apps/frontend/src/main/some-file.ts

# 恢复到合并前的 HEAD
git checkout HEAD~1 -- apps/frontend/src/main/some-file.ts
```

## Q4: 如何查看某个冲突文件的三方版本？

```bash
# 本地版本 (ours)
git show :2:apps/frontend/src/main/ipc-handlers/index.ts

# 上游版本 (theirs)
git show :3:apps/frontend/src/main/ipc-handlers/index.ts

# 共同祖先版本 (base)
git show :1:apps/frontend/src/main/ipc-handlers/index.ts
```

## Q5: 合并后发现漏了一个本地功能怎么办？

```bash
# 从备份分支检出特定文件
git checkout backup/pre-merge-20260221 -- path/to/file.ts

# 或者从 stash 恢复
git stash list
git stash pop stash@{0}
```

## Q6: 构建失败怎么办？

```bash
# 1. 清理并重新安装依赖
cd apps/frontend
rm -rf node_modules/
npm install

# 2. 清理构建缓存
rm -rf dist/ .next/

# 3. 重新构建
npm run build
```

## Q7: 如何确认本地独有功能没有被覆盖？

```bash
# 检查本地独有文件是否存在
ls -la apps/frontend/src/renderer/components/workflow/
ls -la apps/frontend/src/renderer/components/novel/
ls -la apps/backend/novel/

# 检查本地独有 handlers 是否存在
grep -l "novel-handlers" apps/frontend/src/main/ipc-handlers/*.ts
grep -l "skill-handlers" apps/frontend/src/main/ipc-handlers/*.ts
```

## Q8: 如何撤销已经推送的合并？

```bash
# 方法 1: 使用 revert (推荐，保留历史)
git revert -m 1 <merge-commit-hash>
git push origin develop

# 方法 2: 强制回滚 (危险，确保无他人使用)
git reset --hard backup/pre-merge-20260221
git push origin develop --force
```


## Q10: 如何确认上游的 XState 重构已正确合并？

```bash
# 检查状态机文件是否存在
ls -la apps/frontend/src/shared/state-machines/

# 应该看到:
# - pr-review-machine.ts
# - pr-review-state-utils.ts
# - roadmap-feature-machine.ts
# - roadmap-generation-machine.ts
# - roadmap-state-utils.ts
# - terminal-machine.ts
# - task-machine.ts (已存在，应该有更新)
```

## Q11: 如何处理 Python 后端的冲突？

```bash
# Python 文件通常冲突较少
# 如果有冲突，优先采用上游版本，然后手动添加本地功能

# 查看后端冲突文件
git status | grep "both modified" | grep "apps/backend"

# 采用上游版本
git checkout --theirs apps/backend/path/to/file.py
git add apps/backend/path/to/file.py
```

## Q12: 合并后如何测试 XState 功能？

1. **任务状态机测试**:
   - 创建新任务
   - 观察状态变化: backlog → planning → coding → done
   - 验证状态转换是否正确

2. **终端状态机测试**:
   - 打开终端
   - 切换到 Claude 模式
   - 观察状态变化

3. **PR Review 状态机测试**:
   - 打开 GitHub PR
   - 进入 Review 模式
   - 观察状态变化

## 调试命令

```bash
# 查看当前合并状态
git status --porcelain

# 查看合并日志
git log --merge

# 查看所有冲突文件
git diff --name-only --diff-filter=U

# 查看已解决的冲突文件
git diff --name-only --diff-filter=M
```
