## 2. 后端处理策略

### 2.1 一般原则

```bash
# 后端文件通常冲突较少，优先采用上游版本
# 然后手动添加本地功能

# 采用上游版本
git checkout --theirs apps/backend/agents/coder.py
git checkout --theirs apps/backend/agents/session.py
git checkout --theirs apps/backend/core/auth.py
git checkout --theirs apps/backend/core/worktree.py

# 添加到暂存区
git add apps/backend/
```

### 2.2 本地独有后端模块

以下模块是本地独有的，需要确保保留：

```
apps/backend/
├── novel/                    # 小说模块 (必须保留)
│   ├── __init__.py
│   ├── novel_generator.py
│   ├── workflow_runner.py
│   └── ...

│   └── ...
├── security/
│   └── bash_validators.py    # Bash 验证器 (必须保留)
├── runners/
│   └── novel_writer_runner.py # 小说写入运行器 (必须保留)
└── ...
```

## 3. 关键文件处理

### 3.1 `apps/backend/agents/coder.py`

**冲突原因**: 上游有 bug 修复，本地可能有定制

**处理方式**:
```bash
# 1. 采用上游版本 (包含 bug 修复)
git checkout --theirs apps/backend/agents/coder.py

# 2. 检查本地定制功能
# 如果本地有重要定制，需要在新版本基础上重新实现

# 3. 添加
git add apps/backend/agents/coder.py
```

### 3.2 `apps/backend/core/auth.py`

**冲突原因**: 认证逻辑，上游有更新

**处理方式**:
```bash
# 采用上游版本
git checkout --theirs apps/backend/core/auth.py
git add apps/backend/core/auth.py
```

### 3.3 `apps/backend/core/worktree.py`

**冲突原因**: Worktree 逻辑

**处理方式**:
```bash
# 采用上游版本
git checkout --theirs apps/backend/core/worktree.py
git add apps/backend/core/worktree.py

# 注意: 本地有 worktree_helper.py，这是独有的，需要保留
```

## 6. 如果后端启动失败

### 6.1 依赖问题

```bash
# 重新安装依赖
cd apps/backend
pip install -r requirements.txt
```

### 6.2 导入问题

```bash
# 检查具体哪个导入失败
python -c "

sys.path.insert(0, '.')

    print(f'coder FAIL: {e}')

    from core.auth import *

"
```
